# Design: iPhone app for the library (WKWebView shell + offline cache proxy)

Generated by /office-hours on 2026-11-13
Branch: main
Status: APPROVED
Mode: Builder

## Problem Statement
The library already works on a phone through Safari (≤768px layout, mobile
reader, server-rendered PDF pages, bilingual translation). What is missing:
a home-screen app that remembers the server without pasting a token URL,
and reading books when the phone is away from the home LAN.

## Decisions
- **Architecture: WKWebView shell.** The app loads the existing
  `frontend/index.html`; native code only does server connection, the proxy
  and offline storage. Every web feature ships on day one and web changes
  reach the app with no rebuild. Rejected: hybrid SwiftUI shelf (two UIs to
  keep in sync), full native rewrite (weeks of work, re-implements the
  reader and translation).
- **Offline: native caching proxy.** The page is served from a custom scheme
  (`library://app/`) through a `WKURLSchemeHandler`. Every request
  (`/`, `/vendor/*`, `/covers/*`, `/api/*`) is forwarded by native code to the
  saved server with the `lib_token` cookie added, so the token never lives in
  the web layer. Responses for books marked "downloaded" are stored on disk.
  Offline, the proxy answers from that store. Rejected: Service Worker
  (needs a secure context; `http://192.168.x.x` is not one), native offline
  reader (PDFKit + Readium: new dependency, no MOBI/AZW3, no offline
  bilingual view).
- **Connect: paste the LAN URL with token** printed by the server
  (`http://<ip>:8765/?token=…`). Stored in the Keychain; a settings sheet
  lets the user change it.
- **Distribution:** personal use only, installed from Xcode (free Apple ID
  signing expires after 7 days; re-run from Xcode). No App Store, no CI.
- **Minimum iOS 17.** SwiftUI app lifecycle, no third-party packages.

## Offline behaviour
- "下载离线" button in the book detail sheet, shown only inside the app
  (the page detects `window.webkit.messageHandlers.library`). It calls the
  native bridge, which prefetches:
  - `/api/books/<id>` and the cover,
  - text books: `/api/books/<id>/read?chapter=0..N-1` plus every
    `epub_asset` / `mobi_image` URL found in the chapter HTML,
  - PDFs: `pdf_layout`, then `pdf_page/<n>` and `pdf_text/<n>` for all pages.
- Cache key = path + query (`v=` cache-busters on PDF pages are dropped from
  the key). `/read` without `chapter` (resume) is answered offline with the
  chapter of the last locally saved progress.
- Offline shelf: `/api/books` returns only downloaded books, built from their
  stored detail JSON. Endpoints with no cached answer return 503 JSON
  `{"ok": false, "error": "离线不可用"}` so the existing UI shows its error.
- Translations (`/api/translate`, `/api/translate/batch`) are POSTs; their
  responses are cached keyed by a hash of the body, so passages already
  translated online stay bilingual offline.
- Progress: `POST /api/books/<id>/progress` while offline is stored (latest
  per book) and replayed when the server answers again.
- Delete download: from the detail sheet; a settings sheet shows total size.

## Premises (agreed)
1. Personal use, sideloaded from Xcode, no App Store.
2. Translation, AI search and organizing still need the server.
3. iOS 17 minimum.

## Constraints
- Xcode is not installed on this Mac (only Command Line Tools). The user
  chose "write code first": the project is written now and verified in the
  Simulator after Xcode is installed.
- Server endpoints and the token gate stay as they are; the frontend change
  is limited to the in-app download/delete buttons.
- Repo gates: functions ≤50 lines, files ≤500 lines (Python test gate covers
  backend/frontend; Swift files follow the same limits by hand).

## Open Questions
- Large PDFs: prefetching every page image can be hundreds of MB. First
  version downloads all pages with progress shown; page-range download only
  if it hurts.
- Cover thumbnails use `?w=360`; offline cache stores that exact URL only.

## Success Criteria
- Project in `ios/` opens in Xcode and builds for the iOS Simulator.
- First launch: paste token URL → shelf loads, search and filters work.
- Open detail → read an EPUB and a PDF, bilingual toggle works online.
- Download a book, stop the server, relaunch: shelf shows that book,
  reader opens it, progress saved offline reaches the server after restart.

## The Assignment
Install Xcode from the App Store, open it once to add the iOS Simulator
runtime, then run `sudo xcode-select -s /Applications/Xcode.app` so command
line builds work.
